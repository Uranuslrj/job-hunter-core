# Boss 直聘投递助手 · 怎么用

> 一句话：**机器负责捞岗、筛岗、打分、写稿；你负责最后按一下，然后机器慢慢发。**

---

## 一、先跑一次看看效果（不用联网）

双击打开命令行，进到这个目录：

```
cd <你的项目目录>/boss_skill
python run.py --no-ask
```

会看到 10 条样例岗位被筛过一遍：4 条被砍掉（课程销售 / 城市不对 / 日薪太低 / 要三年经验），
剩下 5 条各写了一句招呼语。

**这一步的目的是让你确认：删掉的都是你想删的，留下来的都是你想投的。**

---

## 二、三个文件决定一切

| 文件 | 管什么 | 什么时候改 |
|---|---|---|
| `config/target_roles.yaml` | 城市、薪资下限、岗位族、打分权重、每天发几条 | 你想调整标准时 |
| `config/greeting_spec.yaml` | 招呼语的写法、禁用词、字数、结尾变体 | 你想改话术时 |
| `data/greeting_ledger.csv` | 每一条发出去的记录 | 每天回来填三列 |

**改规则不用改代码。** 比如你想加城市，打开第一个文件把城市名加进去就行。

---

## 三、接真实岗位（要你的浏览器，10 分钟）

这一步必须你亲手做一次 —— 因为登录态得是你自己的。

**第一步**，双击 `启动调试浏览器.bat`。会开一个带着调试口的 Edge（你机器上装的是 Edge，没装 Chrome）。

**第二步**，在这个浏览器里打开 zhipin.com，**自己扫码登录**。

**第三步**，回来跑：

```
python fetch_cdp.py check
```

看到当前页面地址里有 zhipin，就说明接上了。

**第四步**，开始扫：

```
python fetch_cdp.py one
```

| 命令 | 干什么 |
|---|---|
| `check` | 浏览器通没通、登录了没 |
| `scan` | 扫列表页：15 城 × 5 个搜索词 → `data/jobs_list.json` |
| `detail` | 对名字过关的岗位，打开详情页拿 JD 正文 → `data/jobs_today.json` |
| `one` | 上面两步连着跑（日常用这个） |

跑完开始打分：

```
python run.py --input ../data/jobs_today.json
```

> 小提示：一天要跑两三轮的话，把这句记到记事本里，或者让我帮你拼成一个双击就跑的 bat。

## 四、每天怎么用（只差最后一步）

```
python run.py --input ../data/jobs_today.json
```

跑完会列出今天筛出来的岗位，每条带分数和写好的招呼语。然后问你选哪些：

**不想被问**就加 `--auto`：机器按 85 分以上自己勾，直接导出队列，不问你。

```
python run.py --input ../data/jobs_today.json --auto
```

| 你输入 | 会发生什么 |
|---|---|
| `all` + 回车 | 全选（按机器勾的那些） |
| `1,3,5` + 回车 | 只选这几条 |
| `n` + 回车 | 今天不投 |
| 直接回车 | 选机器默认勾的那些（85 分以上） |

**选完之后机器接手**（`delivery.mode: auto_cdp` 时）：把选中的记录写进台账、
导出发送队列，然后由 `send_cdp.py` 一条一条发出去，你不用在场。

同时会生成一张卡片 `data/review_card.html`，双击打开，每条招呼语后面有个**一键复制**按钮 ——
手动补发、或者想自己改两句时用得上。

想退回手动：把 `config/target_roles.yaml` 里的 `delivery.mode` 改成 `confirm_only`。

## 五、发出去之后每天花 3 分钟

打开 `data/greeting_ledger.csv`，把这三列填上：

- `read_24h` —— 一天内对方看了没
- `read_72h` —— 三天内看了没
- `replied` —— 回话了没

**这三列是整套东西唯一的老师。** 不填，我们就永远不知道哪版话术有用。

满 60 条之后告诉我，我帮你算：哪个城市回复率最高、哪个结尾最好用、哪个经历最招 HR 喜欢。

## 六、现在还没做的部分

| 部分 | 状态 |
|---|---|
| 抓列表页（连你的浏览器） | 写了，**第一次跑要你登一次录，跑完我们对着 `data/raw/debug_*.txt` 校准** |
| 抓详情页（拿 JD 正文） | 写了，每天最多开 120 个（配置里 `detail_lookup_daily_cap`） |
| 过滤 / 打分 / 写招呼语 | 能用，样例跑通 |
| 审阅 + 一键复制 | 能用，卡片里带复制按钮 |
| **自动发送**（连点和的消息框都替你点） | **做了，2026-10-27 你本人拍板开的** |

### 自动替你发：三步，别跳

省下的时间不来自"发得快"，而来自"你不用在场盯着"。
每条间隔 12–35 秒，100 条要发 40 分钟 —— **这是故意慢的。**

```
python send_cdp.py probe           ① 探选择器：打开一条岗位，把候选选择器全试一遍，不点任何东西
python send_cdp.py dry-run         ② 演练：走完整流程，最后一步不点发送
python send_cdp.py send --limit 10 ③ 真发（第一天只发 10 条，没事再放开）
```

**第一次跑 `probe` 大概率要校准选择器** —— Boss 页面的真实结构我没见过样本，
所以选择器是猜的。这不是失败，跑一次把输出给我，我照着改。

### 防张冠李戴：六道检查，删一道都不行

| # | 什么时候查 | 查什么 | 不过怎么办 |
|---|---|---|---|
| 1 | 入口 | 每条都从**这条岗位自己的详情页**点进去，绝不在聊天列表找人 | 设计如此 |
| 2 | 点开对话框 | 读公司名 / 岗位名，跟台账对不上 | 跳过这条 |
| 3 | 发之前（本地） | 话里的岗位族对不对、有没有别的公司名混进来 | 跳过这条 |
| 4 | 发之前 | 90 天内同公司同岗位投过没 | 跳过这条 |
| 5 | 输入之后 | 把输入框的字读回来**逐字**比，不一样重输 | 两次不过就停 |
| 6 | 发之后 | 确认这条消息真发给了这个人 | **立刻停机** |

六道检查的离线自测已跑过：造了 7 个场景（全称/简称/相似公司名/岗位不对），
7 个全判对。

### 熔断：出现这些立刻停，不重试

登录掉了 / 出现验证码 / 连续 3 条没过 / 找不到输入框 / 发完回读对不上。

停下来之后机器**不会自己恢复**，会在屏幕上写清楚停在哪一条、为什么停。

### 还留着的一只眼睛

`human_gate: first_of_day` —— 每天第一条会打出来给你看一眼（约 30 秒），你按个 y。
10 条都没出事之后，可以在配置里改成 `none` 彻底不管。

## 七、踩过的坑（别再踩）

- **打分一度把好岗位砍光了。** 原因是"JD 没写应届"被打成 0 分。现在改成：
  只有"AI 含量"和"需求拆解"这两项是硬筛（没有就是 0），其余三项 JD 没提按中性处理。
- **招呼语一度超字数。** 证据老是被截成"BM25 0.6 + Em…"。现在改成字数不够就**换一句更短的经历**，绝不截半个词。
- **同一批消息一度长得一模一样。** 现在每条会对着 JD 挑不同的经历。
- **SOP 里有个繁体错别字**："內容传播"写成繁体，导致永远匹配不上 JD 里的"内容传播"。已修。
