# 衔接流程 + 停止条件（通用，不随领域变）

> 这是框架里"写死"的部分。换任何领域，这一段都不动。

---

## 一、衔接流程

```
任务进来
  │
  ▼
【执行者】收集 + 加工 → 结构化结果（含来源/证据）
  │
  ▼
【批判者】两套清单挑刺 → 缺陷列表（每条带依据）
  │        └─ 有缺陷 → 打回执行者改（最多 2 轮）
  │        └─ 无缺陷 → 通过
  ▼
【本人】看结果 + 缺陷，拍板裁决
  │
  ├─ 用 → 落地
  ├─ 改 → 反馈执行者重来
  └─ 弃 → 记录原因
  │
  ▼
【规则修改（仅本人触发）】批判者反复报同类缺陷
  → 你决定改规则 → 记进该领域 domain.yaml 的规则手册
```

---

## 二、停止条件（堵死无限循环）

| 环节 | 停止条件 | 硬上限 |
|---|---|---|
| 执行者 | 产出结构化结果即可 | 无循环 |
| 批判者 | 连续 1 轮无新缺陷 → 通过 | **2 轮** |
| 整体 | 本人裁决后结束 | — |

**关键**：用"连续 1 轮无新缺陷"作为通过条件，**不用"质量满意才停"**——"满意"没有客观标准，会无限循环。

---

## 三、交接纪律

1. 每次交接用**结构化字段**（JSON），不用自由文本摘要。
2. 每个角色输出里**回带原始任务目标**（"本条为 task_id=xxx 做的"），防目标漂移。
