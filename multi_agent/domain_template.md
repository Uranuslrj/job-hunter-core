# 领域配置模板（换领域填空用）

> 复制本文件到 `domains/<你的领域名>/domain.yaml`，填三样东西即可。
> 角色与流程（README.md + orchestrator.md）一个字都不动。

---

## 一、领域基本信息

```yaml
domain:
  name: "你的领域名"
  description: "一句话说明这个领域要解决什么问题"
```

---

## 二、三样必填的东西

### 1. 外部抓手（这个领域里"对错"靠什么客观依据）

> 填：批判者能拿什么"客观证据"来验证执行者的说法。没有抓手，批判者就是凭感觉挑刺。

```yaml
external_anchors:
  - "..."   # 例：核对 JD 原文
  - "..."   # 例：跑单元测试
  - "..."   # 例：核对引用 URL 是否存在
```

### 2. 指标清单（这个领域的"合格"具体指什么）

> 填：清单 A 查正确性、清单 B 查合规性。每一项都要"可勾选、可验证"，不能是"感觉不错"这种空话。

```yaml
checklist_A_correctness:   # 结论/方案对不对
  - "..."   # 例：引用的来源真的存在、且不是编造
  - "..."   # 例：依据是否曲解了任务原文

checklist_B_compliance:    # 输出合不合规
  - "..."   # 例：遵守了格式规范
  - "..."   # 例：数据真实、没有编造
```

### 3. 规则手册（这个领域不能踩的线）

> 填：批判者清单 B 要对照的"明确规则条款"。也存这里，方便本人改规则。

```yaml
rulebook:
  - "..."   # 例：禁用词列表
  - "..."   # 例：字数限制
  - "..."   # 例：必须遵守的格式规范
```

---

## 三、可选：业务效果定义（补简历第②条短板用）

> 填：这个领域的"业务效果"是什么——注意是"对最终目标有没有用"，不是技术指标。

```yaml
business_metric:
  definition: "..."   # 例：投递后拿到回复的比例
  unit: "..."         # 例：回复率 %
```

---

## 四、填写自检（填完跑一遍）

- [ ] 外部抓手 ≥ 2 个，都是"客观可查"的？
- [ ] 清单每一项都能"勾选判定"，没有"感觉/更全面"这种空话？
- [ ] 规则手册每一条都是"明确可对照"的条款？
- [ ] 业务效果是"对最终目标"，不是技术指标？
