# 多 Agent 协作框架 · 通用骨架（README）

> 这是"执行者 + 批判者 + 人审裁决"三角色通用框架的落地定义。
> 角色与流程**固定不变**，换领域只填三样东西：外部抓手、指标清单、规则手册。

---

## 一、这套框架是什么

一个可复用到任意领域的协作骨架。核心思想一句话：

**单模型自己产出、自己检查会"一起错"（共享盲区）；拆出一个独立的"批判者"，用两套可勾选的指标挑毛病，能抓到另一类错误。**

三角色：
1. **执行者** —— 收集 + 加工，产出结构化方案（含来源/证据）
2. **批判者** —— 用两套清单挑毛病，输出"缺陷列表"，不是重写答案
3. **人（本人）** —— 最终裁决 + 改规则（机器只提案，不自动改）

## 三、三角色定义（通用，不随领域变）

### 执行者（Executor）

- **职责**：读任务 → 收集信息 → 加工比对 → 产出结构化方案。
- **模型**：**DeepSeek-V4-Pro**（便宜、跑量、Agent 能力强）。**不换**。
- **输出格式（固定）**：

```json
{
  "task_id": "...",
  "方案": "结论/做法",
  "依据": ["依据1", "依据2"],
  "引用来源": ["url/文件/数据"],
  "自信度": "高/中/低"
}
```

- **被打回时的改法（2026-11-02 定）**：批判者打回的缺陷如果超过 N 条，执行者**每轮只改前 3 个最严重的**（按"严重度"排），其余留到下一轮。理由：一次改太多会引入新错，反而不如少改稳。

### 批判者（Critic）

- **职责**：用两套清单挑执行者的毛病，输出缺陷列表。
- **模型**：**Step-5-Preview**（首选，与执行者不同家族 + 强推理，GPQA 93.5%，便宜）。备选：Kimi-K3.1-Pro（更强但贵）、Hy3（限时免费）。原则：与执行者换家族，详见 knowledge/model-pick-16.md。
- **两套清单（通用骨架，具体条款在 domain.yaml 填）**：
  - **清单 A（正确性）**：来源/证据是否真实存在？依据是否曲解任务？【多样性剪枝】共享假设是否要挑战？有没有漏掉更优解/反例？
  - **清单 B（合规性）**：是否遵守该领域规则手册？输出字段是否齐全、来源可溯源？数据是否真实？
- **硬规则**：只能挑"有依据的毛病"（指向来源核验 or 规则条款），禁止"感觉不够好"这类空话。
- **空话自检（2026-11-02 定）**：批判者写完缺陷列表后，**逐条自检一遍**——"这条毛病，我能不能指出它违反了哪条规则、或哪个来源核验结果？"指不出的，直接删掉，不许留在缺陷列表里。这是"有依据"和"空话"的判定标准。
- **停止条件**：连续 1 轮无新缺陷 → 通过；**硬上限 2 轮**。

### 人（本人）

- **职责**：裁决（用/改/弃）+ 改规则（写进 domain.yaml 的规则手册）。

## 四、怎么加一个新领域

1. 复制 `domain_template.md` → `domains/你的领域名/domain.yaml`
2. 填三样东西：外部抓手、指标清单 A/B 具体条款、规则手册
3. 角色和流程不动，就能跑。

---

## 五、三条铁律（永远不破）

1. **默认单 Agent，够用就别拆**——只有"独立检查"能带来真价值才启动批判者。
2. **批判者必须有外部抓手，禁止凭感觉挑刺**。
3. **规则修改权在本人**，机器只提案、不自动改。

---

## 六、可复用的"评判标准"库（2026-11-02 定）

有些现成技能的"标准"可以直接搬进批判者的规则手册，但**只搬"标准"，不搬"流程"**。

**已确认可纳入的：knowledge-research 的五条铁律**（当批判者的清单 B 条款用）：

| 铁律 | 变成批判者的哪条挑刺标准 |
|---|---|
| 双源规则（事实要 ≥2 独立来源） | "这条结论是否只有单一来源，该降级为线索？" |
| 矛盾不抹平 | "矛盾是否并列呈现，而不是偷偷选一边？" |
| URL 必须留存 | "每条结论是否带可点击原始 URL？" |
| 人审闸门 | "是否把该人审的内容当成了机器定论？" |
| 缺口优先于编造 | "有没有用'通常来说'这类词掩盖缺口？" |

**为什么只搬标准、不搬流程**：knowledge-research 的九步流程（拆子问题→20轮检索→…）是"重流程"，硬塞给执行者会拖慢速度、还会让执行者越权干"人审"的活。要的是它的**挑刺标准**，不是它的**调研流程**。

**纳入方式**：在某个领域的 domain.yaml 里，把这些铁律写进 `checklist_B_compliance` 即可，框架结构不动。
